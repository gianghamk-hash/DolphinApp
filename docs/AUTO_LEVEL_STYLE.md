# Automatic style on level gains

A real increase in the employee's permanent level now equips a server-selected style in the same RTDB transaction as XP. The preset selects the highest unlocked choice in every cosmetic category: frame, avatar motion, title, banner, name effect, aura, trail and card effect. A deterministic neutral theme is selected from dark (Lv.1), abyss (4), Dolphin/default (8), aurora (12), coral (18), neon (28), cosmic (36), royal (48) and obsidian (55). Seasonal alternatives remain selectable manually. Avatar picture, employee name, Staff ID, revenue and existing XP formulas are preserved.

This applies to verified revenue/work and archive-repair grants, check-in, business/game missions, same-day verified daily top-ups and delayed business missions. A jump across several levels equips the highest attained preset once. `levelPeak` remains permanent; a downward XP correction never unequips or resets a customized style. Receipts, retries and reads at the same level do not reapply presets. Employees may customize immediately afterward through the existing interface endpoint; a later real level gain applies its preset again.

Existing accounts are not restyled merely by opening a profile after deployment. Their current choices remain until their next level gain. The private progress response includes `autoStyleLevel` so congratulations only claim automatic activation when it actually occurred. Automatic equipment increments profile version, and the shared directory now accepts every ID from the authoritative cosmetic catalog instead of silently dropping newer tiers. Linked applications and public rankings reuse those saved choices.

DOL-0001's existing XP sandbox uses the same equipment rules. Its reset explicitly returns style markers, XP, level and effects to the initial state, allowing repeated tests. The Manager APK remains dedicated to DOL-0001 with the existing verified identity binding; no new employee installation workflow or permission was added.

Verification covers every level 1–60, multi-level gains, denied locked selections, a manual edit followed by refresh/duplicate XP/same-level XP, the next level gain, daily and delayed missions, sandbox reset/retest, and directory propagation of all new IDs. The browser avatar/profile acceptance test renders an actual Lv.36 preset and verifies the frame, motion, name effect, theme and subsequent manual editing. Production deployment uses the existing Staff Access, style and secure-XP workflows and introduces no new service, Rules or IAM requirement.
